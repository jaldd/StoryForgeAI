# 阶段 1 续：文风复读防治（style-repeat）- 需求

> 需求来源：阶段 1 续规划条目 1.7-1.9（随本 spec 一并补录）；动机为一部 300 章实测长篇的复盘数据（见 design §1，语料 anonymized）。
> 最高约束：`.specify/memory/constitution.md`。
> 现状证据与详细设计见同目录 `design.md`；任务分解见 `tasks.md`。
> 前置依赖：`specs/quality-gate/`（checker 结构化 issue / fixer 打回闭环 / 质量规则.json 加载）与 `specs/style-loop/`（滚动注入 / de-AI pass）均已实现；本 feature 消费两者资产，不重复建设。
> 条目编号用 C 系列（A1-A37 归 quality-gate、B1-B20 归 style-loop，避免跨 feature 撞号）。

## 1. 背景与问题

quality-gate（1.1-1.4）与 style-loop（1.5-1.6）让**单章**质量被度量、被拦截、被治疗。但实测复盘发现：全部质量门禁都是**单章视角**，而实际发生的文风失效全是**跨章视角**的——单看每一章都合规，连读 20 章就露馅：

1. **收束句复读**：同一收束句全书 79+ 次独立成行（后期卷几乎每章结尾都是它）。checker 与 reviewer 都只看当前章，「本章用了什么结尾」在架构上不可见。
2. **句式模板堆积**：同一比喻句式模板（「像一个人……」）11 次集中在一卷；修正句式（「不是X，是Y」）单卷 40+ 次。metaphor 检查只测标记词**密度**，不测**模板复读**——每章密度合规，跨章堆成口癖。
3. **章节体量均一**：一卷 45 章字数全部落在 5.8-6.0KB（变异系数≈0.02），固定生成长度的痕迹。没有任何统计可见。
4. **预防侧缺负面输入**：writer 的文风输入全是**正面样文**（exemplar + 滚动人工正文），模型不知道自己上一章刚用过什么收束句、什么句式已经超配额——复读是信息缺失的自然结果。
5. **改稿侧缺诊断工具**：复盈权靠人眼翻 300 章；机械可查的复读清单（哪些章、多少次）没有工具产出。

根因总结：**指标成了目标即失效**（Goodhart）。blacklist 禁掉「眼眸」后模型换个词毫无成本；ai_flavor_score 的 freq 组件测「与文风基准的距离」，而 writer 本来就被要求模仿基准——通过检测是构造性的。剩下的 AI 味在结构层，结构层的共性是**跨章重复**。

本 feature 补三件事：**检测**（checker 跨章检查）、**预防**（writer 负面清单注入）、**诊断**（风格体检命令）。

## 2. 术语

- **收束句 / 结尾行**：一章正文最后一个非空行（跳过分隔线与标题行）。文末独立成行的短句，复读的主要载体。
- **归一化**：结尾行去首尾空白与句末标点后的比对形态（「风很轻。」与「风很轻」相等）。
- **参照章**：跨章检查的比对基准 = 人工正文目录（`NOVEL_HUMAN_TEXT`，递归含分卷子目录）按跨卷章序取尾部 lookback 个 .md。实测工作流为「AI 初稿直接写进 `正文/第X卷/`、原位慢慢精修」，初稿与定稿同目录演化——参照集天然含精修后的章，禁则学到的是最新文风。现算读取，不建持久账本（见 design D1/D6）。
- **句式模板**：`质量规则.json` 配置的正则模式（如「像一个人」「不是X，是Y」），配每章配额。词法代理，非语义判断。
- **负面清单（文风禁则）**：注入 writer prompt 的近期重复收束句与句式配额清单——「近期用过什么」，与既有正面样文（「该写成什么样」）互补。
- **风格体检**：对指定目录全量章节的纯代码扫描，产出收束句复读榜 / 句式命中榜 / 分卷字数分布三张清单，服务人工改稿决策。
- **EARS**：`当 <条件> 时，系统应 <行为>` 的验收条目格式。

## 3. 验收标准（EARS）

### 3.1 跨章检查（1.7，检测）

- **C1** 当 checker 执行且规则含 `ending` 键、参照章非空时，系统应将本章归一化结尾行与参照章归一化结尾比对：近期 lookback 章（含本章）同一结尾出现次数 > max_repeat 时，输出结构化 issue（quote=本章结尾行原文，可定位）。
- **C2** 当提取结尾行时，系统应取正文最后一个非空行，跳过 `---`/`***` 分隔行与 `#` 标题行；归一化 = 去首尾空白与句末标点；归一化后长度 < min_chars（默认 3）的结尾不参与比对（超短结尾豁免，防「嗯。」类误伤）。
- **C3** 当规则含 `syntax_patterns` 键且某 pattern 在本章命中次数 > max_per_chapter 时，系统应输出结构化 issue（quote=首个命中句截前 50 字，可定位）。
- **C4** 当规则文件中的 pattern 是非法正则或可零宽匹配时，系统应在加载点 fail-fast（RuntimeError，报错含 pattern 原文；对齐 quality-gate A23 口径，不静默放行）。
- **C5** 当 `ending` / `syntax_patterns` 键缺失、或参照章为空时，系统应跳过对应检查（零误伤；两键全缺 = 行为与现状逐字节一致）。
- **C6** 当跨章检查命中时，issue 应与既有 checker/reviewer issue 同构（quote/problem/fix），并入 `state.issues` 走既有 fixer 打回-复检闭环（修复式打回，好稿不陪葬；零新状态机角色）。
- **C7** 当加载参照章时，系统应从人工正文目录（`NOVEL_HUMAN_TEXT`，递归含分卷子目录，忽略点前缀目录与 `.agent`）按跨卷章序取尾部 lookback 个 .md：卷序由目录名解析（「第X卷/部/册」的中文或阿拉伯数字），章序由文件名尾部数字（如「-01」）；不可解析者回退字典序并排在可解析之后。逐文件现算结尾；不可读文件跳过，不阻断。
- **C8** 当跨章 issue 触发 fixer 打回时，应与既有 issue 共享同一 `review_count` 预算（不另开循环通道，防死循环）。

### 3.2 负面清单注入（1.8，预防）

- **C9** 当构造 writer 的写作上下文且规则已配置（ending 或 syntax_patterns 任一存在）时，writer prompt 应含【近期文风禁则】分节：近期超配额收束句清单（含出现次数）+ 句式配额说明；无内容时整块不占位。
- **C10** 当禁则注入生效时，仅 writer 的 prompt 含该分节；polisher/reviewer/fixer/deai 的 prompt 不受影响（style-loop B5 同哲学：定调归 writer）。
- **C11** 当目录状态与规则不变时，禁则内容应完全确定（同输入两次构造结果相同，纯函数可测）。
- **C12** 当执行 `状态` 命令时，输出应展示跨章禁则状态（参照章数、禁用收束句条数、句式配额条数或未配置提示）——配置静默失效必须可发现（quality-gate Z7 同哲学）。

### 3.3 风格体检（1.9，诊断）

- **C13** 当用户执行 `风格体检 [目录]` 时，系统应递归扫描目录（默认 `NOVEL_HUMAN_TEXT` 目录）下全部 .md/.txt，输出三节报告：收束句复读榜（归一化结尾按出现次数降序，达到阈值的全列，附文件清单）、句式命中榜（各 pattern 总次数 + 超配额章节清单）、字数分布（按顶层子目录分组：章数/最小/最大/均值/变异系数，另附全局行）。
- **C14** 当体检执行时，全程零 LLM 调用（纯代码，同输入同输出）。
- **C15** 当目录不存在或无可扫描文件时，系统应提示后正常退出（不崩 REPL）。

### 3.4 兼容

- **C16** 当规则文件不含任何新键、或参照章为空时，`写`/`精修`/`重写` 全链路行为应与 style-loop 完成态逐字节一致（双降级）。
- **C17** 当 replay/compare/run_tests 消费旧 run 记录时，系统应正常工作（跨章 issue 复用既有 `state.issues` 留痕机制，无新字段，天然兼容）。
- **C18** 当为 `精修`/`重写`/`去AI` 命令构造参照集、且被处理文件位于人工正文目录内时，该文件自身应从参照集中排除（防自比双计：被精修的章既是「本章」又在参照窗内，count+1 口径下阈值实际被抬高了一档）。

## 4. 非目标（明确不做）

1. **不做字数方差的 checker 拦截**：字数均一是生成期问题，单章稿件无法归因（fixer 修不了「字数太均匀」）；体检只报告。生成期抖动（target_words 随机化）归 P1 任务，校准后再定去留。
2. **不做模糊结尾匹配**：编辑距离/子串/语义相似不做——归一化完全相等，确定性优先（子串会把「嗯。」这类超短结尾全灭，靠 min_chars 豁免足够）。
3. **语义级句式判断不进 checker**：这句话是不是「解释性比喻」只有 LLM 能判，归 reviewer 维度（quality-gate 非目标 3 同边界）。
4. **不动 ai_flavor_score 三组件**：freq 组件改「自相似」方向（与自己最近 N 章比，而非与基准比）是研究性变更，需回测数据支撑，另立 feature（见 tasks P1 T9）；本 feature 不碰。
5. **不做持久风格账本**：不建 `.agent/style_ledger.json` 之类状态文件；章节文件即唯一真源，指纹现算（见 design D1）。
6. **不动滚动注入 / exemplar / 样文路由**：负面清单是追加的独立分节（style-loop 非目标 3 同款边界）。
7. **不做伏笔回收接口**（阶段 3.1）；**不动批量/API 模式**（阶段 2）；**不改 `改` 命令交互**。
8. **回归基线全绿**：`cli/` 下 `python -m pytest tests/ -q` = 566 passed / 0 failed / 1 deselected（2026-09-06，planner 完成态）；本 feature 验收口径为**保持全绿**。
9. **不做卷序修正**：中文数字卷名（第一/二/三卷）的字典序 ≠ 章序，体检按目录分组规避（design Z3），全局排序类统计不做。
10. **planner 不注入禁则**：节拍是结构层（场景/冲突/钩子），收束句与句式是散文层；定调归 writer（D5 同哲学），planner prompt 零改动。

## 5. 宪法对齐表

| 宪法条款 | 约束要点 | 本 feature 的对齐方式 |
|---|---|---|
| §1 项目身份 | 代码仓库零具体小说名 | 句式模板/阈值全部进 `NOVEL_DIR` 的 `质量规则.json`；prompt 模板与报告文案零小说名；复盂数据在 spec 中 anonymized |
| §2 技术栈 | 零新依赖 | 跨章检查/体检是纯代码（re 标准库）；零 LLM 调用；不碰 RAG/embedding |
| §3 存储与路径 | 小说数据在仓库外 `NOVEL_DIR` | 参照章从既有 `chapter_path` 读；体检默认 `human_text_full`；无新落盘文件（非目标 5） |
| §4 推理预算 | token 预算意识 | 检测零 LLM；禁则分节有界（收束句 ≤ 条数上限、句式 ≤ pattern 数）；fixer 修复复用既有「只传问题段」管线 |
| §5 模块边界 | 依赖注入、纯函数优先、agent 不 import cli | 指纹提取/比对/报告为 checker.py 纯函数；接线经 `NovelAgent.__init__` 注入（同 recent_human 先例）；命令在 cli 层 |
| §6 开发流程 | spec-kit 三件套 | 本目录即三件套 |
| §7 验收纪律 | 单测绿、不破基线、离线可测 | 全部测试离线（tmp 目录构造章节文件）；真实语料体检属人工验收（零 LLM、零联网） |
