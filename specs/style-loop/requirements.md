# 阶段 1 后半：文风闭环（style-loop）- 需求

> 需求来源：`specs/ROADMAP.md` 1.5-1.6 条目（L151-164）。
> 最高约束：`.specify/memory/constitution.md`。
> 现状证据与详细设计见同目录 `design.md`；任务分解见 `tasks.md`。
> 前置依赖：`specs/quality-gate/`（T1-T11）已实现--本 feature 消费其 AI 味分（`ai_flavor_score`）、结构化 issue 与回填管线，不重复建设。
> 拍板记录（2026-08-29）：阶段 1 拆两个 feature，本 feature 为后半（开放问题 3）。
> 条目编号用 B 系列（A1-A37 已被 quality-gate 占用，避免跨 feature 撞号）。

## 1. 背景与问题

quality-gate 让质量**被度量、被拦截**，但文风问题只诊断不治疗，且预防侧缺一门输入：

1. **学人味缺位**：writer 的文风锚定静态 exemplar（精选清单，不随写作演进）；`正文/新/` 下的人工正文随写作增长，是比静态样文丰富得多、且**动态**的文风样本，目前只被 AI 味统计消费（`load_baseline`），写作侧零注入。
2. **去 AI 无治疗手段**：quality-gate 的 AI 味分只度量不进门禁（A29）；checker 命中黑名单词交 fixer 做「删词换写」的机械修复，没有「按人的笔性重写」的专向能力。
3. **polisher 方向跑偏**：polisher 的 prompt 只管流畅有文采，不知道 AI 味为何物，有时反而往 AI 味方向润（堆叠副词、拉长从句）。
4. **治疗无验收闭环**：ROADMAP 1.6 要求「重写后 AI 味分必须下降才接受」--该闭环在 quality-gate 中明确划归本 feature。

本 feature 补上闭环的两半：**学人味**（滚动人工正文注入，防）与**去 AI 味**（人味重写 pass，治）。

## 2. 术语

- **人工正文**：`NOVEL_HUMAN_TEXT` 目录（默认 `正文/新`）下的人写章节。quality-gate 已建该配置（AI 味基准语料之二），本 feature 写作侧复用同一目录。
- **滚动窗口**：按文件名序取人工正文目录**尾部** N 个文件的确定性选取（不用语义检索，ROADMAP 1.5 明确：主题相似≠文风相似）。
- **人味重写（de-AI pass）**：专向一轮润色--情节/人称/称呼/伏笔不动，只改表达，目标是降低 AI 味分。
- **AI 味分**：quality-gate 的 `ai_flavor_score`（0-100，越高越 AI），本 feature 的治疗标尺。
- **问题句**：可定位到原文的文风问题载体（checker 结构化 issue 的 quote 命中句、超长句、独白块等；`ai_flavor_score` 的组件定位）。
- **EARS**：`当 <条件> 时，系统应 <行为>` 的验收条目格式。

## 3. 验收标准（EARS）

### 3.1 动态文风注入（1.5，学人味）

- **B1** 当构造 writer 的写作上下文时，文风输入应为「静态 exemplar（精选清单/路由，现状不动）+ 滚动最近 N 章人工正文片段」两部分并存；N 与每章截断长度在配置中可调。
- **B2** 当人工正文目录未配置、不存在或为空时，系统应回落为现状（仅 exemplar），不报错、不阻断写作（零误伤原则）。
- **B3** 当滚动注入执行时，选取应完全确定（同目录状态两次构造结果相同，纯函数可测）；按文件名序取尾部 N 个，文件名序即章序约定。
- **B4** 当注入累计超出可配预算（总字数上限）时，系统应按序截断并留一行日志（对齐 exemplar 的截断纪律），不静默丢内容。
- **B5** 当注入生效时，仅 writer 的 prompt 含人工正文块；polisher/reviewer 的 prompt 不受影响（ROADMAP 1.5 只说 writer 的文风输入；polisher 职责是润色不是定调，reviewer 要的是尺度稳定）。
- **B6** 当执行 `状态` 命令时，输出应展示滚动注入状态（目录、可用文件数、本次注入字数或未配置提示）--配置静默失效必须可发现（quality-gate Z7 同哲学）。
- **B7** 人工正文目录不应进入 RAG 索引（维持 `index rebuild` 排除正文目录的现状）；滚动注入是直接读文件，不走向量库。
- **B8** 当滚动注入启用时，writer prompt 中人工正文块应以明确分节呈现（如「近期人工正文（学笔性，非模仿情节）」），与「必须遵守的设定」等既有分节同风格，避免被模型当成情节指令。

### 3.2 去 AI 润色 pass（1.6，去 AI 味）

- **B9** 当一章流水线完成且 AI 味分超过可配阈值（`质量规则.json` 中新增 de-AI 触发配置）时，系统应执行人味重写 pass；阈值未配置时该 pass 完全不启用（零行为变更）。
- **B10** 当构造重写输入时，系统应只传**问题句及其上下文**，不传整章（token 预算，宪法 §4）；问题句来源为可定位的文风问题（机械检查命中的句子），定位协议复用 quality-gate 的结构化 issue。
- **B11** 当执行重写时，铁律应为：情节、人物人称、称呼、伏笔、段落结构不动，只改表达（去 AI 高频词、拆长句、破独白堆叠）；重写 prompt 应明确「学基准语料的句法节奏」而非泛泛「更有文采」。
- **B12** 当重写回填时，应复用既有段落级回填管线：被改段之外逐字节不变（0.4/quality-gate 已建机制）。
- **B13** 当重写完成时，系统应复检 AI 味分：**下降才接受**；未下降（持平或上升）则保留重写前稿件并在 log 留痕（防越改越糟；比较口径见 design 拍板）。
- **B14** 当 pass 执行（无论接受与否）时，run record 应留痕：pass 前后 AI 味分、重写段数、接受/回退结论（replay 可查）。
- **B15** 当用户在 REPL 需要时，应能对指定已存章节文件手动触发去 AI pass（命令形态见 design；人是标尺，治疗应可主动发起）。
- **B16** 当 pass 修改稿件时，情节保真应可验证：`run_tests` 应能断言关键情节要素（人物名、地名等语料级要素）在 pass 前后未变。
- **B17** 当 pass 无法定位任何问题句（无机械命中且 AI 味分未超阈值，或超阈值但无句可定位）时，系统应跳过 pass 并留痕，不空跑 LLM、不无限循环。

### 3.3 兼容与预算

- **B18** 当所有新配置项缺失/为零值时，系统行为应与 quality-gate 完成态逐字节一致（滚动注入与 de-AI pass 双降级）。
- **B19** 当 de-AI pass 在流水线内触发时，应与既有 `max_reviews` 打回预算协同（不另开无限循环通道；具体预算归属见 design 拍板）。
- **B20** 当 replay/compare 消费旧 run 记录（无 pass 留痕字段）时，系统应正常工作。

## 4. 非目标（明确不做）

1. **AI 味分不进门禁**：维持 quality-gate A29 的拍板--AI 味分只度量与展示；de-AI pass 是治疗不是拦截，治疗后过不过门禁仍由既有 eval_gate 说了算。
2. **不做语义检索选样**：滚动窗口 + 固定精选，简单确定（ROADMAP 1.5 原文否决）。
3. **不动 exemplar 机制**：精选清单（0.5b）、样文路由（exemplar-routing）零改动；滚动注入是**追加**的独立块。
4. **不重写整章**：只改问题句与问题段，其余逐字节不变（好稿不陪葬，quality-gate D1 同哲学）。
5. **不做模型微调/风格迁移**：零新模型依赖，纯 prompt 工程（宪法 §2 技术栈不动）。
6. **不引入分词**：沿用字 + bigram 口径（宪法 §5 纯函数可测优先）。
7. **不动批量/API 模式**：本 feature 只覆盖 REPL 人在环路径（同 quality-gate 边界）。
8. **不改 `改` 命令交互**：partial.py 管线被复用但对外行为零改动（quality-gate 同款边界）。
9. **不修存量 3 个失败测试**（`test_strip_polisher_meta`、`test_runtime_dir_override`、`test_defaults`）：无关既有失败，纪律是零新增。
10. **不做文风漂移检测/告警**：滚动注入本身就是漂移的跟随机制，显式检测留给回测数据说话后另议。

## 5. 宪法对齐表

| 宪法条款 | 约束要点 | 本 feature 的对齐方式 |
|---|---|---|
| §1 项目身份 | 代码仓库零具体小说名 | 滚动目录/阈值/截断全部走配置（`NOVEL_HUMAN_TEXT` 已有 + 新 env 见 design）；prompt 模板零小说名；run_tests 的情节保真断言从文件/规则取要素，不硬编码人名 |
| §2 技术栈 | LLM/embedding/向量库锁定、零新依赖 | 滚动注入是纯文件读取；de-AI pass 走既有 `writer_llm` 路由与 4096 档；不碰 RAG |
| §3 存储与路径 | 小说数据在仓库外 `NOVEL_DIR` | 人工正文即 `NOVEL_DIR` 既有目录；新配置项进 `.env copy.example` 注释段；run record 留痕仍落 `.agent/runs/` |
| §4 glm-5.2 推理预算 | 长输出 4096、token 预算意识 | B10 只传问题句不传整章；滚动注入有总字数预算（B4）；每次 pass 恰一轮 LLM 调用（B17 防空跑） |
| §5 模块边界 | 依赖注入、纯函数优先、agent 不 import cli | 滚动选取函数纯函数化（可单测）；de-AI pass 挂 `NovelAgent`（agents 注册，同 fixer 先例）；确认缝在 cli 模块级 |
| §6 开发流程 | spec-kit 三件套 | 本目录即三件套 |
| §7 验收纪律 | 单测绿、不破基线、离线可测 | 全部测试用 FakeLLM/FakeRag/monkeypatch 离线注入；AI 味分下降断言用构造语料驱动（一稿 AI 味重、修复稿人味重），不依赖真实模型 |
