# 需求：文风基准按章路由（exemplar-routing）

> Feature: `exemplar-routing`
> 遵循 `.specify/memory/constitution.md`；对应阶段 0.5b 规划的动态化延伸（阶段 1.5 的前置实验）。

---

## 1. 背景与问题

### 1.1 现状

`写第N章` 时 exemplar 的注入路径（0.5 实现）：

- `cli._build_agent` 启动时 `load_exemplar(文风基准/)` 一次性加载；
- 目录级加载 = `00-使用说明.md` 全文 + 全部 14 篇样文（无 `## 注入清单` 节时回退全量），合计 ~3 万字顶到 `EXEMPLAR_MAX_CHARS=30000` 上限；
- exemplar 只进 writer 的 system prompt（polisher/reviewer 不带），每章付一次。

### 1.2 问题

1. **token 浪费**：每章 writer 吞 3 万字样文，而小说的《每章.md》每章只对应一种场景（日常/退缩/天气拉扯…），14 篇全量注入大部分与本章无关。
2. **锚定模糊**：用户《00-使用说明.md》第五节自述「不要每次把 14 篇全塞进去。太多了，AI 反而会糊」。样文场景混杂时文风锚点反而弱。
3. **静态清单不够**：0.5b 的 `## 注入清单` 是静态的（改一次全局生效），无法按「本章要写什么」动态选择。

### 1.3 用户已有资产（本 feature 的直接消费方）

- 《每章.md》：每章一条「核心事件 + 天气」描述——路由的查询信号；
- 《00-使用说明.md》第五节「挑样文的方法」：场景→样文映射的领域知识雏形；
- 14 篇样文各 1100~3000 字——路由的候选池。

---

## 2. 用户故事

- US1：作为作者，我希望写第 N 章时 Agent 自动从《每章.md》取本章描述，挑 3-5 篇最贴的样文注入 writer，而不是全量 14 篇——省钱且锚定更准。
- US2：作为作者，我希望样文的「擅长场景」描述集中在一个随小说走的标签文件里，我改一行字就能调整路由依据，不动代码。
- US3：作为作者，路由失败（模型抽风/解析失败/选了不存在的文件）时写作不能中断，要回落到确定行为。
- US4：作为作者，我希望在 REPL 里能看到「本次路由选了哪几篇、为什么」，不放心可以核对。
- US5：作为作者，`精修`/`重写`/`改` 命令也应受益（它们同样构建 agent 加载 exemplar），至少不劣化。

---

## 3. 功能需求

### F1 样文标签文件

- `文风基准/样文标签.md`（文件名可配 `NOVEL_EXEMPLAR_TAGS`，相对 NOVEL_DIR；留空=禁用路由走现状）。
- 格式：每行一条 `- <文件名>: <一行场景/味道描述>`；带 `#` 标题与说明文字（注入路由 prompt 时仅取列表行）。
- 文件不存在 → 路由禁用，`load_exemplar` 行为与现状完全一致（fail-open 到 0.5 逻辑）。

### F2 路由调用（写命令前置一步）

- 触发：`写第N章：...` 命令，且标签文件存在且可解析出 ≥1 条标签。
- 输入：本章任务描述（命令原文）+ 全部标签行。
- 输出：JSON `{"files": ["5.txt", ...], "reason": "..."}`，files 为选中的样文文件名列表。
- 约束：走主 LLM 配置（非 writer_llm），`max_tokens≥1024`（宪法 §4），温度用低值（路由要稳不要飘）。
- 每章路由结果进 run 记录（config 段或独立字段），replay 可见。

### F3 按需加载

- 路由成功：exemplar = `00-使用说明.md` 全文 + 选中样文按清单序拼接；仍受 `EXEMPLAR_MAX_CHARS` 截断。
- 路由失败/禁用：回落 `load_exemplar` 现状逻辑（注入清单 → 全量截断），打一行提示。

### F4 REPL 可见性

- 路由结果打印：选中文件名 + reason（一行）。
- `状态` 命令显示标签文件是否启用及条数。

---

## 4. EARS 验收标准

- A1：标签文件不存在时，`写`/`精修`/`重写`/`改` 行为与本 feature 前逐字节一致（回归保险）。
- A2：标签文件存在且路由成功时，writer system prompt 中的 exemplar 只含说明全文 + 选中样文，不含未选中样文正文。
- A3：路由 LLM 返回不可解析 JSON 时，写作继续，exemplar 回落现状加载，控制台有提示。
- A4：路由返回的 files 中不存在的文件名被跳过并提示；全落空时回落现状加载。
- A5：run 记录含本次路由的 files/reason，`replay` 能看到。
- A6：选中样文总字数超 `EXEMPLAR_MAX_CHARS` 时按序截断并提示（复用 0.5 截断逻辑）。
- A7：`改`（partial_refine）不额外注入 exemplar（维持现状，不新增 token 消耗）。
- A8：`grep 云依 cli/` 零命中（宪法 §1）；标签文件、路由 prompt 中不含具体小说名。
- A9：全部新增逻辑有单测覆盖（fake LLM 路由成功/失败/空选/文件缺失四分支）。

---

## 5. 非目标

- 不做 embedding 检索标签（14 条用不上向量检索）。
- 不做多轮路由或标签自动生成（LLM 代打标签初稿可作为使用建议写在文档里，不进代码）。
- 不改 `00-使用说明.md` 的注入地位（说明全文仍作首块，0.5b 语义不变）。
- 不动 polisher/reviewer 的注入面（exemplar 仍只进 writer）。
