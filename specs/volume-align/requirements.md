# 卷对齐落盘（volume-align）- 需求

> 需求来源：真车使用发现（2026-09-05，3.2 验收期间）——用户小说为卷结构
> `正文/第N卷/第N卷-NN.md`（每卷 60 章、**卷内章号从「第一章」重计**，头行
> `## 第三十八章 空`），AI 产出却落 `正文/第38章-空.md`（平铺 + 异构头行），
> 与原稿不是同一文件，git 无法直接比对；用户被迫手动搬文件 + 改头行。
> 最高约束：`.specify/memory/constitution.md`。
> 拍板（2026-09-05）：AI 章直接覆盖卷内原稿（git diff 即比对）；走 spec-kit。
> 条目编号用 V 系列（A/B/T/F/W/C 已被既有 feature 占用）。

## 1. 背景与问题

用户工作流是**逐章重写既有小说**：commit 原稿 → AI 重写某章 → git diff 审改动 →
满意则 commit、不满意 `git checkout --` 回退。当前三处不对齐使该流程断裂：

1. **目录**：原稿在 `正文/第一卷/`，AI 章落 `正文/`（`NOVEL_CHAPTER_SUBDIR=正文`）；
2. **文件名**：原稿 `第一卷-38.md`（卷名+卷内章号，无标题），AI 章 `第38章-空.md`；
3. **头行**：原稿 `## 第三十八章 空`（## + 中文数字），AI 章 `第38章 空`
   （模型其实输出了正确格式，被 `save_chapter` 剥掉后按代码格式重写）。

## 2. 验收标准（EARS）

- **V1** 当 `NOVEL_VOLUME_ALIGN=1` 且任务章号可解析时，`save_chapter` 应把章节
  存到 `{chapter_subdir}/{卷名}-{章号:02d}.md`（卷名 = `NOVEL_CHAPTER_SUBDIR`
  的末段目录名，如 `正文/第一卷` -> `第一卷`），文件名不含标题（重写换标题时
  文件名不动，diff 干净）。
- **V2** 当卷对齐落盘时，头行应为 `## 第{中文数字}章 {标题}`（复用 `cn_numeral`，
  与人工原稿约定一致）；章号 > 99 时回落阿拉伯数字（`## 第105章`），不崩。
- **V3** 当目标文件已存在时，应**直接覆盖**（不加 run_id 后缀）——git diff 即
  比对、`git checkout --` 即回退；run record 另存全文，双保险。
- **V4** 当任务章号解析不出（`num=None`，如「写一段番外」）时，应回落现状命名
  （run_id），不覆盖任何文件。
- **V5** 当 `NOVEL_VOLUME_ALIGN=0`/未设时，落盘行为与本 feature 前现状逐字节
  一致（`第NN章-标题.md`，同名加 run_id 后缀不覆盖）。
- **V6** `parse_chapter_file` 应兼容卷文件名 `第N卷-NN.md`（返回 `(NN, "")`），
  使精修/重写存回后的工作记忆刷新（`_refresh_working_memory`）在卷文件上生效；
  判定序：先既有「第N章-标题」格式，后卷格式（防「标题2」类文件名误判）。
- **V7** `.env copy.example` 应有「卷对齐落盘」注释段：开关用法、前提
  （`NOVEL_CHAPTER_SUBDIR` 指到当前卷目录）、换卷工作流（改 subdir + 改
  `NOVEL_HUMAN_TEXT` 指向未重写卷 + 删 working_memory.json 重置）、
  人工语料自我污染警示。
- **V8** 既有兼容：旧格式章节文件（`第05章-标题.md`）解析不变；RAG 入库对
  同名卷文件重复写入是稳定 id upsert（不产生重复块）；旧 run record 不受影响。
