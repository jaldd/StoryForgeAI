# 需求规格：局部精修（partial-refine）

> Feature: `partial-refine`
> 来源：`specs/ROADMAP.md` 条目 0.4「局部精修（快赢）」
> 状态：**已复核（2026-08-28 证据核验通过；文档修订已应用；R1 全程可取消 / R2 分段 diff 已采纳），可开工**
> 遵循 `.specify/memory/constitution.md`。

---

## 1. 背景与目标

### 1.1 现状痛点（均有代码证据，详见 design.md §2）

现有 `精修` / `重写` 命令只作用于**整章**：

- 只想改一小段，也得整章过「polisher -> reviewer」流水线（`cli/novel_agent/cli.py:219-252`、`cli/novel_agent/agent.py:368-400`）；
- 好段落陪着返工，且整章覆盖存回有把好段落润坏的风险——字数保护只看长度不看内容（`cli/novel_agent/agent.py:256-261`）；
- token 按整章付：polisher 全文一次、reviewer 全文一次，强制定稿时再加全文对比一次、存回后再跑全文评测一次。

### 1.2 目标

新增命令 `改 <文件路径>`：列出段落编号 → 人选段 → 只润色选区 → 按段落区间整块回填（其余部分逐字节不变）→ 回填前 diff 确认 → 存回后该文件重新入索引。

**设计原则（沿用 ROADMAP 已定结论）**：

- **局部模式跳过 reviewer：人选段 + diff + 确认，人就是门禁**（符合 ROADMAP 门禁总原则「机器拿不准时交给人」）。
- token 按**选区**计，不按整章计。
- 产出的「选区+上下文 → 改写 → 回填」管线做成可复用工具，ROADMAP 1.6 的去 AI pass（自动版：checker 找问题句）直接复用。

## 2. 用户故事

```
作为小说作者，我想：

1. 输入「改 第05章-异乡风起.md」
   -> Agent 列出该文件全部段落的编号与预览
   -> 我输入「3-5」选择要改的段落
   -> Agent 只润色第 3-5 段（带前后各一段上下文），其余段落不动
   -> 我看到只含选区的差异展示（原文 -> 改后）
   -> 我输入 y 确认，文件存回，向量库同步更新
   -> 第 6 段及之后的内容与改前逐字节一致

2. 我输入「3,7」一次选两处不相邻的段落，两处分别改写、一次确认、一起存回

3. 我在确认环节输入 n，文件保持原样，什么都没发生（可以重新选段再来）

4. 我选段时输错了（如「99」），Agent 告诉我错在哪，让我重新输入，不会误改
```

## 3. 功能列表

### P0（必须做）

- [ ] 新命令 `改 <文件路径>`（相对 `NOVEL_DIR` 或绝对路径，与 `精修` 一致）。
- [ ] 段落编号列表：按空行切块；`---`（场景分隔符）与文件头章节标题**跳过编号但保留**；每段展示编号 + 预览 + 字数。
- [ ] 选段解析：支持 `3`（单段）/ `3-5`（连续区间）/ `3,7` / `3-5,7`（组合）；非法输入（超范围、区间倒置、非数字）给出原因并要求重新输入；空回车或 `q` 取消。
- [ ] 选区级润色：只送「选区 + 前后各一段上下文」给 polisher，要求只返回选区改写结果；**跳过 reviewer**（人是门禁）。
- [ ] 区间整块回填：按段落区间整块替换，其余部分（含换行符、BOM、`---`、章节头）**逐字节不变**。
- [ ] 回填前 diff + y/n 确认；差异展示只含选区内容，不含选区外段落。
- [ ] 存回后该文件重新入索引（复用现有 `rag.add_document`，先删旧块再 upsert）。

### P1（应该做）

- [ ] run 日志留痕：`partial_` 前缀的 run 记录（选区、原文/改后文本、确认结果），`replay` 可读。
- [ ] LLM 返回异常警告：改后文本长度相对选区突变（过度膨胀/骤减）时打印 ⚠️ 警告，不拦截（确认环节兜底）。
- [ ] `help`、`cli.py` 模块 docstring、`cli/README.md` 命令表同步更新。

### P2（可以做）

- [ ] 确认时输入 `r` 重新生成（不满意 diff 不必退出重来）。
- [ ] 「选区+上下文 → 改写 → 回填」管线接口固化，供 ROADMAP 1.6 去 AI pass 复用。

## 4. 验收标准（EARS 式）

> 编号 A1… 供 tasks.md 引用。`逐字节不变` 的工程口径见 design.md §5.3：选区外字节序列与原文件完全一致（含 `\r\n`、BOM、文件尾）。

### 命令与段落列表

- **A1** 当用户输入 `改 <路径>` 且文件存在、非空时，系统应列出全部段落，格式为「编号: 预览（字数）」，其中 `---` 块与文件头章节标题不占编号但内容完整保留。
- **A2** 当用户输入 `改 <路径>` 但文件不存在或为空时，系统应打印错误提示且不进入选段交互。
- **A3** 当文件切分后不存在任何可编号段落（仅标题/分隔符）时，系统应提示「无可选段落」并退出命令。

### 选段

- **A4** 当用户输入合法选段（`3` / `3-5` / `3,7` / `3-5,7`）时，系统应接受并展示选区统计（段数、总字数）后进入润色。
- **A5** 当用户输入非法选段（编号为 0 或超出最大编号、区间倒置如 `5-3`、含非数字字符）时，系统应打印具体原因并要求重新输入，不得启动 LLM 调用。
- **A6** 当用户在选段提示下直接回车或输入 `q` 时，系统应取消本次操作，文件不被读取修改。

### 润色与回填

- **A7** 当润色进行时，系统发给 LLM 的用户消息应包含且仅包含：选区文本 + 前后各一段上下文（带明确标记），不得包含选区外其余正文。
- **A8** 当 LLM 返回非空改写结果时，系统应只把改写文本回填到对应段落区间，选区外所有字节保持不变。
- **A9** 当用户改了 3-5 段后，其余段落（含 `---` 与章节头）应与原文件逐字节一致。
- **A10** 当展示差异时，系统应仅输出选区原文与改后文本的 diff，不输出选区外内容；多区间时按区间分段展示（各选区独立 diff）。

### 确认与落盘

- **A11** 当用户在确认提示输入 `y` 时，系统应将回填后全文写回原文件，并调用 `rag.add_document` 更新该文件的向量块。
- **A12** 当用户在确认提示输入 `n`（或其他非 `y` 内容）时，系统应放弃修改，原文件字节不变，不更新向量库。
- **A13** 当命令任一环节（选段/生成/确认）被 Ctrl-C / Ctrl-D（EOF）打断时，系统应视为取消本次操作（不写文件），且 REPL 主循环不因此退出。

### 失败路径

- **A14** 当 LLM 多次重试后仍返回空内容时，系统应打印失败提示，文件不被修改。
- **A15** 当改写结果长度超过选区原文 3 倍或不足 1/3 时，系统应在 diff 前打印 ⚠️ 长度异常警告，但仍进入人工确认（人是门禁，不自动拦截）。
- **A16** 当 `rag.add_document` 更新索引失败时，系统应打印警告但保留已写回的章节文件（与现有 `精修` 行为一致）。

### 留痕（P1）

- **A17** 若实现 P1 留痕，当用户确认存回后，系统应生成 `partial_` 前缀的 run 记录，含选区区间、选区原文、改后文本与确认结果；`replay <run_id>` 可读出改写结果。

## 5. 非目标（范围纪律）

- **不做** reviewer 接入局部模式——ROADMAP 已定「局部模式跳过 reviewer，人就是门禁」。
- **不做**自动定位问题句（那是 ROADMAP 1.6 去 AI pass 的事），本 feature 只提供手动选段的管线。
- **不做**多文件批量修改、跨文件操作。
- **不做**语义级段落理解（按空行机械切块；对 markdown 列表/引用块不做特殊处理）。
- **不动** `精修` / `重写` 现有命令行为（它们的问题记录在 design.md §9 开放问题，属其他 ROADMAP 条目）。
- **不做**选区长度/上下文窗口的配置化（避免过度工程；见开放决策）。

## 6. 约束（宪法对齐）

| 宪法条款 | 对本 feature 的约束 |
|----------|---------------------|
| §1 小说解耦 | 命令操作任意 `NOVEL_DIR` 下文件，路径不硬编码；代码仓库不出现具体小说名 |
| §2 技术栈 | 交互用内置 `input()`，不引入 CLI 框架；无新第三方依赖（diff 用标准库 `difflib`） |
| §3 存储路径 | 文件读写在 `NOVEL_DIR` 下；run 记录、向量库走现有路径约定 |
| §4 glm-5.2 | 润色属长输出，LLM 调用 `max_tokens=4096`（与现有 polisher 一致） |
| §5 模块边界 | 段落切分/选段解析/回填为**纯函数**可单测；LLM 调用走 `LLMClient`；依赖注入不变；测试 mock LLM 不联网 |
| §7 验收纪律 | P0 验收 = ROADMAP 0.4 三条：改 3-5 段后其余段落逐字节不变；`---` 与章节头保留；差异展示只含选区 |
