# StoryForgeAI 小说创作操作手册

> 面向使用者。想看开发者文档（架构/测试/spec）请移步 [README.md](README.md)。

---

## 1. 这是个什么东西

一个跑在终端里的**小说创作助手**。你用一句中文下命令，它自动完成一整条流水线：

```
查设定（RAG 检索你的小说资料）
   ↓
写草稿（writer 角色）
   ↓
润色（polisher 角色）
   ↓
审稿（reviewer 角色）──不合格──→ 打回润色重改（最多 6 次）
   ↓ 合格
存文件 + 记住剧情摘要（下一章能接上前文）
   ↓
自动打分（连贯性 / 人物一致性 / 剧情合理性 / 标题）
```

核心思想：**你的小说资料（设定、文风、正文）放在一个独立目录里，Agent 每次写作前先"查阅资料"再动笔**，所以它写的东西贴你的设定、像你的文风，而不是凭空编。

## 2. 第一次使用：从零到写出第一章

### 第 1 步：装环境

需要 Python 3.11+。在 `cli/` 目录下执行：

```bash
cd cli
pip install -e .
```

### 第 2 步：配置 .env

把 `cli/.env copy.example` 复制一份到**仓库根目录**，改名为 `.env`，填三样东西：

```ini
ARK_API_KEY=你的火山引擎密钥     # 必填
NOVEL_NAME=我的小说              # prompt 里显示的书名
NOVEL_DIR=D:/novel/mynovel      # 你的小说内容根目录（建议放仓库外）
```

> `.env` 已被 gitignore，密钥不会被提交。
> 模型默认 `glm-5.2`，想换用 `CLAUDE_MODEL=模型名` 覆盖。

### 第 3 步：准备小说目录

`NOVEL_DIR` 指向的目录按下面的样子组织：

```
D:/novel/mynovel/
├── 总纲.md            # 世界观、主线剧情（RAG 索引源）
├── 人物.md            # 角色设定（RAG 索引源）
├── 伏笔.md           # 伏笔清单（RAG 索引源）
├── 写作指令.md        # 全局硬规则（每次写作全文注入，见第 3 节）
├── 写作铁律.md        # 底线铁规（每次写作全文注入，见第 3 节）
├── 文风基准/
│   └── 1.txt         # 文风金标准（每次写作全文注入，见第 3 节）
├── 正文/
│   ├── 新/           # 你自己写的章节
│   └── AI生成/       # Agent 产出的章节（自动存这里）
└── .agent/           # 运行时数据（自动生成，不用管）
```

### 第 4 步：建向量库（首次必做）

```bash
cd cli
python -m novel_agent
```

看到 `>>>` 提示符后输入：

```
>>> index
```

这一步把你的设定文件（总纲/人物/伏笔等，**不含正文**）向量化存库。以后写作时 Agent 靠它检索资料。设定文件改了之后，用 `index add 文件名` 单独更新，或 `index rebuild` 全量重建。

### 第 5 步：写第一章

```
>>> 写第1章：雨夜来客
```

然后等它跑（几分钟，取决于模型速度）。结束后会打印：流程日志 → 最终章节全文 → 自动评测分数。章节文件已存到 `NOVEL_DIR/正文/AI生成/` 下。

## 3. 喂什么料，出什么文

产出质量的上限由你的三个"料"决定，值得花心思：

### 文风基准（`文风基准/1.txt`）——决定"像不像你写的"

放 1~2 段你认为**"就该是这个味"**的正文（自己写的或最想模仿的），几百到两千字。它会被**全文塞进**每次写作的 prompt 里让模型照着模仿。

要点：
- 挑你最能代表目标风格的段落，宁精勿多
- 短句节奏、留白方式、对话密度这些"味儿"就是从这里学的

### 写作指令（`写作指令.md`）——决定"红线在哪"

全局硬规则，**全文注入**、不靠检索，所以适合放"每章都必须遵守"的约束：

- 人称与视角（第几人称、单视角还是多视角）
- 禁忌（禁出现什么词、什么情节）
- 章节结构偏好（开头结尾方式、每章大致节奏）

写法建议：一条一行、命令式、别写长篇解释。跟设定相关的细节**不要**放这里（放设定文件，让 RAG 按需检索），这里只放"铁的"。

### 写作铁律（`写作铁律.md`）--决定"底线在哪"

和写作指令一样**全文注入**写作/润色/审稿三个环节，但语气更重（prompt 里标注"绝对不能违反"，审稿官也按它审）。分家建议：

- **指令**（必须遵守）：常规约束，如"第三人称单视角""每章 1500 字上下"
- **铁律**（绝对不能违反）：碰了就是废稿的底线，如人物称呼规则、核心意象含义、叙事禁忌

铁律文件不存在则不注入，不报错。

### 设定文件（`总纲.md` / `人物.md` / `伏笔.md`……）——决定"事实对不对"

写作时按需检索最相关的几段，所以：

- **重要角色单独一个文件**，别挤在一个大文件里
- 每个设定点写成**自包含的段落**（"林晚，19 岁，怕黑，从不主动问别人隐私"——检索到这句模型就懂了；拆成三处散落就可能漏）
- 设定改了记得 `index add` 重新入库

## 4. 写命令详解

### 用法

任何以"写"开头的行都是写作命令：

```
>>> 写第5章：异乡风起
```

### 它内部干了什么

1. **查资料**：从你的总纲/人物/伏笔里检索与本章最相关的片段，连同文风基准、写作指令一起装进 prompt
2. **查前情**：读工作记忆（前面章节的剧情摘要、角色状态、未回收伏笔），保证连续性
3. **草稿 → 润色 → 审稿** 循环：审稿官按人物/文风/剧情/时间线/环境/伏笔六个维度审，不合格打回重润色（最多打回 6 次）
4. **落盘**：章节存到 `NOVEL_DIR/正文/AI生成/`
5. **记前情**：自动生成 1~2 句剧情摘要存入工作记忆，写第 6 章时它还记得第 5 章发生了什么
6. **打分**：四个维度各 1~5 分，附总评和建议标题

### 输出怎么读

- **`--- 流程日志 ---`**：每轮谁干了什么、审稿意见是什么。审稿打回多说明这章写得费劲，看看 issues 里反复出现什么问题，往往值得回去改设定文件
- **`=== 最终章节 ===`**：成品全文
- **`--- 自动评测 ---`**：`连贯性 / 人物一致性 / 剧情合理性 / 标题评分` 各 1~5 分。某维长期低于 3 分，通常是设定文件或文风基准没喂到位
- **`运行日志：...runs/run_xxx.json`**：这次写作的完整记录，run_id 后面 replay/eval/compare 都用得上

## 5. 不满意怎么办：改稿四板斧

| 工具 | 命令 | 动多大 | 适用场景 |
|------|------|--------|----------|
| **局部精修** | `改 文件` | 只改你选中的几段 | 90% 的修改场景：某几段写崩了、某句太 AI 味 |
| **精修** | `精修 文件` | 全文润色（不动情节） | 整章文字质量不行但情节没问题 |
| **重写** | `重写 文件` | 参考原文推倒重写 | 情节方向就不对，或者嫌太短想扩写 |
| **手改** | 随便编辑器 | 自己动手 | 你就是最好的编辑；改完记得 `index add 文件` |

选型心法：**改动面越小越好**。能用 `改` 就别精修，能精修就别重写——改动越小，AI 弄坏其他段落的风险越小。

### 精修 / 重写 的存回规则（重要，别被吓到）

两者都要过审稿，规则相同：

- **审稿通过** → 自动覆盖存回原文件，更新索引
- **审稿不过但质量优于原文** → 覆盖存回
- **审稿不过且不优于原文** → **原文件一动不动**，结果只存在运行日志里（用 `replay run_xxx` 查看）

所以如果命令跑完发现"文件怎么没变"，先去看流程日志里的审稿意见，不是出 bug 了。

## 6. `改` 命令详解（局部精修）

只润色你圈选的段落，**选区之外一个字节都不动**（含换行、`---` 分隔符、章节标题）。

### 完整交互实录

```
>>> 改 正文/AI生成/第05章_异乡风起_run_20260828.md

共 7 个块，5 段可编号：
  [章节头] ## 第5章 异乡风起
1: 她在巷口站了很久，风把外套吹得贴在身上。（24字）
2: 林晚从她身边走过，没有回头。（15字）
  [分隔符] ---
3: 他记得那天的雨下了整夜，修车铺的灯一直亮着。（23字）
4: 没人说话。有些话一旦出口，就再也收不回来。（21字）
5: 天亮的时候，雨停了。（10字）

选段（如 3 / 3-5 / 3,7；回车或 q 取消）：3-4

已选 2 段（第3-4段），共 44 字。

  🔧 局部润色中（第3-4段，约30秒）...

=== 局部精修差异（选区原文 -> 改后）---

--- 第3-4段 ---
--- 原文
+++ 改后
@@ -1,2 +1,2 @@
-他记得那天的雨下了整夜，修车铺的灯一直亮着。
-没人说话。有些话一旦出口，就再也收不回来。
+他记得那场雨下了整夜。修车铺的灯亮到天明，没人去关。
+谁都没说话。有些话出口就收不回，索性咽下去。

确认存回？(y/n)：y

✅ 已存回：D:/novel/mynovel/正文/AI生成/第05章_异乡风起_run_20260828.md
📝 运行日志：...runs/partial_20260828_153012.json
📚 更新向量库...
```

### 选段语法

| 输入 | 意思 |
|------|------|
| `3` | 只改第 3 段 |
| `3-5` | 改第 3、4、5 段 |
| `3,7` | 改第 3 段和第 7 段（分别润色、分别展示 diff） |
| `3-5,7` | 组合 |
| `3 7` | 空格等同逗号 |

注意：
- **用半角逗号**，全角 `，` 会被拒绝重输（错误提示会告诉你）
- 编号只数正文段：章节标题和 `---` 分隔符展示但不占编号
- 输错随时重输；**回车或 `q` 取消**；**任何环节按 Ctrl-C 都安全取消**（文件保证未动）

### 看到这些提示怎么办

- `⚠️ 第X-Y段长度异常：N 字 -> M 字` —— 模型疑似返回了整章或内容坍缩。**仔细看 diff**，不对就选 `n` 放弃
- `❌ 模型未返回内容` —— 这轮模型抽风了，重跑一次命令即可，文件没动

## 7. 质检工具箱

### 状态

```
>>> 状态
```

看当前写到第几章、最近剧情、角色状态、未回收伏笔、共跑了多少次、生成了几个章节文件。**写文前看一眼**，心里有数。

### replay（回放）

```
>>> replay run_20260828_103000
```

重放某次写作的完整过程：每一步是哪个角色、打回了几轮、最终章节是什么。`改` 命令的留痕是 `partial_` 开头的 run_id，同样可 replay（显示"共 0 步"+回填后全文）。

### eval（打分）

```
>>> eval run_20260828_103000
```

对某次写作独立打分（四个维度各 1~5 分 + 建议标题）。写完自动评过一次，想单独重评再用它。

### compare（对比）

```
>>> compare run_20260828_103000 run_20260828_140000
```

两次写作并排对比。同一章用不同指令/文风基准各写一次后对比，调教手感利器。

### test（规则断言）

```
>>> test run_20260828_103000
```

跑规则型检查（不调模型）。快速过一遍基本项。

## 8. 索引管理（index 家族）

向量库是 Agent 的"记忆"，设定变了要让它知道：

| 命令 | 作用 |
|------|------|
| `index` | 查看库状态 + 帮助 |
| `index add 人物.md` | 单个文件改了，重新入库 |
| `index remove 人物.md` | 从库里移除 |
| `index rebuild` | 全量重建（遵守排除规则，默认不索引正文） |

什么时候 rebuild：设定文件**大面积**修改/重命名/删除后。日常小改用 `add` 就够。

## 9. 配置速查（.env）

| 变量 | 默认 | 说明 |
|------|------|------|
| `ARK_API_KEY` | 必填 | 火山引擎密钥 |
| `CLAUDE_MODEL` | `glm-5.2` | 写作模型 |
| `NOVEL_NAME` | `本小说` | prompt 里的书名 |
| `NOVEL_DIR` | 必填 | 小说内容根目录 |
| `NOVEL_CHAPTER_SUBDIR` | `正文/AI生成` | Agent 章节存放子目录 |
| `NOVEL_EXEMPLAR` | `文风基准` | 文风金标准（目录或单文件，相对 NOVEL_DIR；目录下全部 .txt/.md 按序注入） |
| `NOVEL_INSTRUCTION` | `写作指令.md` | 写作指令（相对 NOVEL_DIR） |
| `NOVEL_RULES` | `写作铁律.md` | 写作铁律（相对 NOVEL_DIR；留空不加载） |
| `NOVEL_INDEX_EXCLUDE` | `正文` | 建索引时排除的目录（逗号分隔） |
| `NOVEL_RUNS_DIR` | `<NOVEL_DIR>/.agent/runs` | 运行日志位置 |
| `NOVEL_CHROMA_DIR` | `<NOVEL_DIR>/.agent/chroma_db` | 向量库位置 |
| `STORYFORGE_ROOT` | 当前目录 | 找 `.env` 用的仓库根 |

## 10. 常见问题

**Q：章节存到哪里了？**
`NOVEL_DIR/正文/AI生成/` 下。别和 `正文/新/`（你手写的）混了。

**Q：精修/重写跑完，文件怎么没变？**
审稿没过且新版不优于原文，文件保持原样。看流程日志里的审稿意见，用 `replay` 查看那次的结果。这是保护机制，不是 bug。

**Q：写着写着想中断，Ctrl-C 安全吗？**
- `改` 命令：**任何环节 Ctrl-C 都安全**，文件保证未动
- `写`/`精修`/`重写`：中断即本次作废（已写完存盘的章节不受影响）
- `>>>` 提示符处按 Ctrl-C 或 Ctrl-D：退出程序

**Q：觉得章节太短？**
用 `重写 文件`（writer 参考原文重写，能大幅扩写）。同时检查文风基准是不是选了太精简的段落。

**Q：写出来的内容跟设定冲突？**
1. 检查设定文件里相关设定是否写成了自包含段落（见第 3 节）
2. `index add` 确认最新设定已入库
3. 跑 `replay` 看当时的检索命中了什么

**Q：怎么换一本书写？**
改 `.env` 里的 `NOVEL_NAME` 和 `NOVEL_DIR` 指向新书的目录，新书首次记得 `index` 建库。Agent 跟具体小说是解耦的。

**Q：API 报错 / 超时？**
自动重试若干次后仍失败会返回空结果。重跑一次命令即可；连续失败检查 `ARK_API_KEY` 和网络。

## 11. 写文最佳实践

1. **料比命令重要**：文风基准 + 写作指令喂得好，能省掉一半改稿
2. **一章一气呵成**：写完看分、用 `改` 微调，别反复重写同一章（越重写越平庸）
3. **勤看状态**：`状态` 里的"未回收伏笔"定期清一清，挖了坑要填
4. **设定即真理**：发现写错了设定，先改设定文件再 `index add`，再动正文
5. **大改之后 rebuild**：设定目录大动（重命名/删除/重组）后 `index rebuild` 一次
6. **每次产出都有 run_id**：不满意的版本别急着骂，`eval` 打个分留档，方便对比调教前后的效果
